# BTC Signal Engine — Agent Guidance

## Project Overview

Production-grade BTC/USDT trading signal engine + dashboard.

- **Next.js App Router** — dashboard UI + API route handlers (signal engine endpoints)
- **Worker process** — `node-cron` scheduler calling same core functions
- **Drizzle ORM** — type-safe SQL, schema-as-code
- **PostgreSQL** — persistence
- **Redis** — bias cache + deduplication

## Non-negotiables

- Every price/quantity uses `Decimal` from `decimal.js`. **Never `number`. Ever.**
- All times are UTC in code. Only convert to UTC+7 (Asia/Bangkok) at display boundary.
- Bar close timing: use Binance `closeTime`, not `openTime + interval`. Filter to `closeTime <= now`.
- No business logic in `app/api/*` or `worker/*` — they orchestrate. Logic lives in `src/core/`.
- Fail loud: no silent error swallowing. Log then re-throw.

## Architecture: How the pieces connect

```
[node-cron worker]              [Next.js API routes]
  ├── :00 every 1H  ──────────→  POST /api/signal-1h
  ├── 00:00 UTC daily ─────────→  POST /api/bias-1d
  └── every 5min ──────────────→  POST /api/position-manager
                                         │
                                    [src/core/*]  ← pure logic
                                         │
                              [Drizzle ORM + PostgreSQL]
                                         │
                              [Next.js Dashboard pages]
                                 reads from same DB
```

## Build Order (STRICT)

1. Phase 1: Foundation — Next.js setup, Drizzle schema, types, tooling
2. Phase 2: Core — indicators + tests, strategy + tests, risk + tests
3. Phase 3: Backtest — validate before any I/O work (gate must pass)
4. Phase 4: Adapters + API routes + Worker
5. Phase 5: Dashboard UI

## Phase 3 Gate (must pass before Phase 4)

- Total trades > 50
- Win Rate > 30%
- Profit Factor > 1.25
- Max Drawdown < 25%
- Results within ±5% of TradingView Pine backtest

## When adding a strategy variant

1. Add config params to `StrategyConfig` in `src/core/types.ts`
2. Update `checkEntry` / `evaluateExit`
3. Add unit tests
4. Run `yarn backtest` and compare metrics before merging

## Testing discipline

- Every pure function in `src/core/` must have unit tests (Vitest)
- Integration tests use real Postgres (never mock the DB)
- `yarn test` must pass before any commit touching `src/core/`

## Common pitfalls

- **EMA repaint**: closed bars only
- **Off-by-one in indicators**: first `period-1` bars return `undefined` — guard it
- **TP qty math**: TP2 closes "30% of original" = 50% of remaining (match Pine behavior)
- **Timezone bugs**: Binance timestamps are ms UTC — always `.toISOString()` for logs
- **ATR uses RMA (Wilder's smoothing)**, not SMA
- **EMA seed**: SMA of first `period` values, not first close

## Commands

```bash
yarn dev              # Next.js dev server (dashboard + API routes)
yarn worker           # Start node-cron worker (separate terminal)
yarn test             # Vitest unit tests
yarn db:generate      # drizzle-kit generate (after schema change)
yarn db:migrate       # drizzle-kit migrate
yarn db:studio        # Drizzle Studio (local DB GUI)
yarn validate-indicators  # compare vs TradingView (must be ±0.01%)
yarn seed-history     # pull 2y BTC data
yarn backtest         # run LOOSE-3 backtest, print report
```
